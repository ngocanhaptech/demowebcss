1. Tổng quan & lý do chọn Next.js

Với một website clone lấy cảm hứng Tailscale — nặng về marketing, SEO và nội dung động do admin quản trị — Next.js là lựa chọn tốt hơn React/Vite. Bốn lý do trực tiếp:

Ưu thếTác động thực tế
SEO tốt hơnServer rendering + generateMetadata cho từng route: title, description, canonical, Open Graph đều có sẵn khi crawler tải trang, không phụ thuộc JS hydration.
Server ComponentsRender nội dung MongoDB ngay tại server, không expose endpoint nội bộ, không tạo client-side fetch waterfall, không lộ credential.
Route HandlersThay thế hoàn toàn Fastify API cho phạm vi MVP: lead form, auth, admin CRUD — cùng một codebase, cùng một deploy.
Vercel zero-configDeploy gần như không cấu hình; mọi route dưới app/api/ tự động trở thành Function.

1.1 Giới hạn phạm vi — điều kiện để lựa chọn này đúng

Next.js / Vercel PHÙ HỢP
  • CMS-lite — nội dung có cấu trúc, số lượng editor nhỏ, workflow draft → publish đơn giản.
  • Landing page & marketing site — hero, feature grid, use case, pricing, security page.
  • Lead capture — contact form, demo request, newsletter, kèm consent tracking.
  • Admin CRUD — quản trị page, quản trị lead, phân quyền theo role.
Next.js / Vercel KHÔNG phù hợp
  • Tác vụ AI / inference dài — vượt giới hạn thời gian thực thi của Function.
  • Worker & job queue chạy liên tục — serverless không giữ process nền.
  • WebSocket / kết nối bền — cần server thường trú, không phải Function.
  • Media pipeline — transcode, resize hàng loạt, xử lý binary lớn.

Với các nhu cầu trên, tách riêng service (Fly.io / Railway / Render / VPS) và để Next.js chỉ đóng vai trò web + BFF.

1.2 Nền tảng cấu trúc App Router

Next.js App Router dùng cấu trúc thư mục để định nghĩa route. Các file quy ước:

FileVai trò
page.tsxUI của route, tạo ra URL public.
layout.tsxShell bao quanh, giữ state khi điều hướng giữa các route con.
loading.tsxSuspense fallback tự động cho segment.
error.tsxError boundary phía client cho segment.
not-found.tsxUI cho notFound() và 404.
route.tsAPI endpoint dùng Web Request/Response chuẩn.

MongoDB cũng có hướng dẫn tích hợp Next.js bằng Node driver kết hợp Route Handler tại app/api/.../route.ts, nên cấu trúc trong tài liệu này khớp với App Router hiện tại.

4. Giới hạn MongoDB Atlas M0

Atlas M0 miễn phí nhưng có các giới hạn đáng chú ý cần thiết kế xoay quanh:

Giới hạnHệ quả thiết kế
0.5 GB tổng data + indexChỉ lưu CMS data và lead nhỏ. Không lưu media, không lưu raw analytics, không lưu event stream.
~100 ops/giâyBắt buộc cache public page. Không để mỗi page view sinh một query Atlas.
500 connectionsBắt buộc dùng client singleton cache theo globalThis, không tạo MongoClient mới mỗi request.
Giới hạn data transfer theo cửa sổ 7 ngàyProjection chỉ lấy field cần; tránh trả toàn bộ document cho danh sách.
Không có managed backupPhải tự lên kế hoạch mongodump/export định kỳ. Không coi M0 là source of truth duy nhất cho lead thật.
Bốn nguyên tắc bắt buộc
  1. Chỉ lưu dữ liệu nhỏ — CMS content và lead; asset đẩy sang object storage.
  2. Tạo index đúng theo query — không để collection scan trên leads hay pages.
  3. Cache public page — Next Data Cache + tag-based revalidation.
  4. TTL cho audit log — tự động dọn sau 90 ngày để giữ dung lượng ổn định.

Hình 5.1 — Cây thư mục: route group tách marketing/admin, feature layer theo Clean Architecture-lite.

5.1 Điểm chính

  • Route group (marketing) và (admin) không xuất hiện trong URL, nhưng cho phép hai layout.tsx hoàn toàn khác nhau.
  • Public page ưu tiên Server Components — tránh gọi API vòng lại chính server của bạn.
  • Chỉ thêm "use client" vào: form, interactive menu, table filter, page editor, animation canvas.
  • Feature layer theo thứ tự domain → application → infrastructure → presentation.
  • app/api chỉ xử lý HTTP: auth → validate → gọi use case → response.
  • Không viết MongoDB query trực tiếp trong React component hoặc page.tsx.

10.4 Route Handler cho lead form

// app/api/leads/route.ts
import { NextResponse } from "next/server";
import { createLeadSchema } from "@/schemas/lead.schema";
import { createLead } from "@/features/leads/application/create-lead";

export const runtime = "nodejs";

export async function POST(request: Request) {
  try {
    const body = await request.json();
    const parsed = createLeadSchema.safeParse(body);

    if (!parsed.success) {
      return NextResponse.json(
        {
          error: "Please check the form fields.",
          fields: parsed.error.flatten().fieldErrors,
        },
        { status: 422 },
      );
    }

    if (parsed.data.website) {
      return new NextResponse(null, { status: 204 });
    }

    const lead = await createLead(parsed.data);

    return NextResponse.json(
      {
        id: lead.id,
        message: "Thanks — we'll be in touch shortly.",
      },
      { status: 201 },
    );
  } catch (error) {
    console.error("Unable to create lead", error);

    return NextResponse.json(
      { error: "Unable to submit the form. Please try again." },
      { status: 503 },
    );
  }
}

Route Handlers dùng standard Web Request/Response API và nằm trong file route.ts; đây là cơ chế API đúng cho Next App Router. Trường website là honeypot — bot điền vào thì trả về 204 im lặng.

11. Caching & Revalidation

11.1 Cache tại tầng use case

// features/content/application/get-published-page.ts
import { unstable_cache } from "next/cache";
import { mongoPageRepository } from "../infrastructure/mongodb-page.repository";

export async function getPublishedPage(slug: string) {
  return unstable_cache(
    async () => mongoPageRepository.findPublishedBySlug(slug),
    ["published-page", slug],
    {
      revalidate: 300,
      tags: [`page:${slug}`],
    },
  )();
}

11.2 Invalidate khi admin publish

import { revalidateTag } from "next/cache";

11.3 Mục tiêu

  • Public page không đọc Atlas quá thường xuyên — bảo vệ quota 100 ops/giây.
  • Sau publish, cache content bị invalidate sớm thay vì chờ hết TTL.
  • Không dùng client polling để lấy homepage content.
Lưu ý phiên bản

Cần cân nhắc API cache của Next/Vercel theo phiên bản đang dùng (unstable_cache, "use cache", cacheTag…). Hãy viết test publish → refresh public page để xác minh behavior thực tế trên môi trường production, không chỉ trên dev server.

12. Auth & Middleware

Middleware rất tốt để redirect sớm user chưa có session khỏi /admin, nhưng không dùng middleware như lớp authorization duy nhất. Vercel middleware có thể chạy với matcher theo path, do đó nên giới hạn nó cho /admin/:path* và tránh chạy trên toàn bộ asset/public route.

// middleware.ts
import { NextRequest, NextResponse } from "next/server";

export function middleware(request: NextRequest) {
  const token = request.cookies.get("meshflow_session")?.value;

  if (!token) {
    const loginUrl = new URL("/admin/login", request.url);
    loginUrl.searchParams.set(
      "next",
      `${request.nextUrl.pathname}${request.nextUrl.search}`,
    );

    return NextResponse.redirect(loginUrl);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/admin/:path*"],
};

12.1 Defense in depth — bắt buộc trong mọi POST /api/admin/**

  1. Đọc cookie session từ request.
  2. Verify JWT signature và kiểm tra session expiry.
  3. Load hoặc trust role claim theo chính sách đã chọn.
  4. Kiểm tra permission editor / owner tương ứng hành động.
  5. Chỉ sau đó mới gọi use case mutation.

14. Giới hạn nền tảng & đường nâng cấp

14.1 Rủi ro cần theo dõi

  • Public read traffic cần cache — nếu mỗi request đều query MongoDB, bạn có thể sớm chạm quota/limit Atlas.
  • Serverless cold start + Mongo network latency vẫn có thể xảy ra, đặc biệt sau thời gian idle.
  • Không dùng Atlas M0 làm sole source of truth cho lead/customer data quan trọng nếu chưa có export/backup.
  • Không lưu vào M0: media, event stream, session trace, raw analytics.
  • Vercel serverless không phải nơi chạy Fastify server, worker lâu, WebSocket hoặc job queue liên tục.
